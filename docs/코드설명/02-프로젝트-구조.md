# 2장. 프로젝트 구조와 흐름

## 폴더 지도

```
dadok/
├─ index.html              브라우저가 처음 여는 파일
├─ package.json            사용하는 라이브러리와 실행 명령어
├─ vite.config.js          개발 서버 설정 (백엔드·YES24 연결)
├─ eslint.config.js        코드 검사 규칙
├─ .env.local              비밀 값 (YES24 키, 백엔드 주소). git 에 안 올라감
├─ dist/                   npm run build 결과물. git 에 안 올라감
├─ docs/코드설명/           지금 읽는 문서
└─ src/
   ├─ main.jsx             리액트 시작점
   ├─ App.jsx              주소 ↔ 화면 연결표
   ├─ routes.js            주소 이름 모음
   ├─ global.css           전체 공통 스타일 (글꼴 등)
   ├─ api/                 여러 화면이 같이 쓰는 서버 호출
   ├─ hooks/               여러 화면이 같이 쓰는 커스텀 훅
   ├─ components/          여러 화면이 같이 쓰는 컴포넌트
   ├─ images/              이미지
   └─ pages/               화면별 폴더
      ├─ landing/          로그인 전 첫 화면
      ├─ legal/            이용약관, 개인정보 처리방침
      ├─ auth/             로그인, 회원가입, 아이디·비밀번호 찾기
      ├─ home/             홈
      ├─ bookSearch/       책 검색 (서재 저장소 bookStore 도 여기)
      ├─ myLibrary/        서고 (나의 서재 / 공동 서재 / 독서 달력)
      ├─ sharedLibrary/    공동서재 상세
      ├─ review/           감상문
      ├─ quote/            인용구 노트
      ├─ timer/            독서 타이머
      ├─ weeklyRank/       주간 경쟁
      └─ myPage/           마이페이지, 회원정보 수정
```

화면 폴더 안의 파일은 이름 규칙이 있어요.

| 파일 | 역할 |
|---|---|
| `Home.jsx` | 화면 (컴포넌트) |
| `Home.css` | 그 화면의 모양 |
| `homeApi.js` | 서버 호출과 데이터 가공 |
| `xxxStore.js` | 브라우저 저장소 읽고 쓰기 |
| `useXxx.js` | 그 화면 전용 커스텀 훅 |

## 실행하면 벌어지는 일

```
npm run dev
   ↓ Vite 개발 서버가 켜진다 (localhost:5173)
브라우저가 index.html 을 연다
   ↓ <script src="/src/main.jsx">
main.jsx 가 <App /> 을 #root 칸에 그린다
   ↓
App.jsx 가 주소를 보고 맞는 화면을 고른다
   ↓
화면 컴포넌트가 그려지고, useEffect 에서 데이터를 불러온다
   ↓
데이터가 오면 setState → 화면이 다시 그려진다
```

## 사용자가 움직이는 길

```
/ ──→ /auth/guest_page (첫 화면)
          ├─ 약관 → /terms, /privacy
          └─ 로그인 → /auth/log_page
                       ├─ 회원가입 → /signup
                       ├─ 찾기 → /auth/idpw_found
                       └─ 성공 → /home

사이드바 (Layout 안의 화면들)
  마이페이지 /mypage ──→ 회원정보 수정 /mypage/edit
  홈        /home
  주간 경쟁  /rank
  책 검색    /search
  서고       /library ──→ 공동서재 /shared-library
                      ──→ 감상문   /review
  (인용구)   /quote  ←── 홈의 오늘의 문장
  설정       /settings (아직 비어 있음)

사이드바 없는 화면
  타이머 /timer ←── 서고·책 상세·주간 경쟁의 '바로 읽기'
```

타이머 흐름:

```
서고에서 '바로 읽기' → 목표 시간 입력 → 읽는 중 → 책 덮기 → 쪽수 입력 → 감상문 쓰기
```

## 데이터는 어디에 있나요

세 곳에서 와요. 코드를 읽을 때 "이 값은 어디서 왔지?"를 먼저 보세요.

| 어디 | 무엇 | 파일 |
|---|---|---|
| **YES24 API** | 책 표지, 제목, 소개, 베스트셀러 | `bookSearchApi.js` |
| **백엔드** | 로그인, 순위, 마이페이지, 퀘스트 | `api/auth.js`, `*Api.js` |
| **브라우저 localStorage** | 서재, 감상문, 인용구, 리뷰, 프로필 사진 | `bookStore.js`, `quoteStore.js`, `myImages.js` |

### localStorage에 저장되는 값 전체 목록

| 키 | 내용 | 쓰는 파일 |
|---|---|---|
| `token`, `refreshToken` | 로그인 토큰 | `App.jsx`, `api/client.js` |
| `user` | 로그인한 내 정보 | `App.jsx`, `bookStore.js` |
| `myLibraryBooks` | 나의 서재 | `bookStore.js` |
| `sharedLibraryBooks` | 공동 서재 | `bookStore.js` |
| `bookReviews` | 책 리뷰 | `bookStore.js` |
| `bookAdders` | 책을 서재에 담은 사람 | `bookStore.js` |
| `bookCommentaries` | 감상문 | `bookStore.js` |
| `quotes` | 인용구 | `quoteStore.js` |
| `readingLog` | 날짜별 읽은 시간 | `timerApi.js`, `libraryApi.js` |
| `myImage:아이디:profile` 등 | 내 프로필·배경 사진 | `myImages.js` |
| `attendanceDate:아이디` | 오늘 출석했는지 | `attendance.js` |
| `weekResultShown:아이디` | 지난주 결과 알림을 봤는지 | `WeeklyRank.jsx` |

## 파일끼리 어떻게 연결되나요

예시로 '나의 서재 추가' 버튼을 따라가 볼게요.

```
BookDetail.jsx          <button onClick={() => onAddMine(book)}>
     ↑ props
BookSearch.jsx          const addMine = async (b) => { await addToMyLibrary(b); showToast(...) }
     ↓ import
bookStore.js            addToMyLibrary: 서버에 보내고 localStorage 에도 저장
     ↓ import
api/client.js           requestServer: 실제 fetch
```

대부분 이 모양이에요. **화면 → 데이터 함수 → 서버/저장소** 순서로 내려가요.
